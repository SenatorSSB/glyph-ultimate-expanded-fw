## GP-CONFIG-006 — truthful transaction-stage reporting in the existing GP-CONFIG-005 host/operator utility

**Planner readiness estimate:** `CURATION_READY` (a non-authoritative estimate
for independent Curator judgment, not READY or PREAUTHORIZED authorization).

**Classification:** H1.

**Objective:** Make the existing host-side hardware operator utility truthfully
record transaction stages, so a serial response timeout cannot incorrectly
imply that no request was written.

**Value and current source evidence:** At audited canonical
`13a0e76e4de39f6fc7e9c80d210315cb19adf316`,
`tools/glyph_serial_config_tool.py` performs `write_all(encoded)`, then
`read_packet()`, then decodes the response in `PosixSerialPort.transact()`
without emitting transaction-stage information. In
`tools/gp_config_005_hw_test.py`, `execute_valid_update()` sets `sent` only
after `transport.transact(CMD_SET_CONFIG, payload)` returns. If the write
completes but waiting for a response times out, that exception path leaves
`sent` false and reports a transport/follow-up stop. The resulting operator
record cannot distinguish a pre-write failure from a completed write followed
by an absent response. This is a truthfulness/reporting gap in host tooling;
it is not evidence of changed firmware behavior or a claim about device-side
commit/persistence.

**Expected scope:**

- the existing host/operator tooling transport and valid-update result record;
- focused host-side tests for successful write, write failure, response timeout,
  and follow-up timeout stage boundaries;
- directly required operator-protocol correspondence, inventory, manifest, or
  census metadata only when current validation contracts require it.

**Explicit exclusions:**

- firmware behavior, active firmware source, and hardware artifacts;
- protocol or wire-operation changes, including any new command or device-side
  behavior;
- GP-CONFIG-005 evidence reinterpretation, a new hardware result, persistence
  guarantees, or a claim that a written request was accepted;
- GP-VAL-011 and all work on its owner-deferred repair;
- runtime-loaded config, WebSerial/device-write expansion, protobuf/schema
  work, flashing automation, modifier/layout semantics, and unrelated product
  features.

**Prior-work evidence, not publication authority:** unpublished historical
commit `8b2c8932304ecf5c56149eb91ec5ddd7511c59e8` records a previously working
stage-callback approach across `glyph_serial_config_tool.py`,
`gp_config_005_hw_test.py`, and its tests. It is not an ancestor of the
audited canonical SHA and must not be published, cherry-picked, or merged
wholesale. It is evidence to inspect and reconcile against current canonical

**Dependencies and validation boundary:** The eventual Implementation
