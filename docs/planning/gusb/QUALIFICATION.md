## Where the original path fails

| Stage | Evidence and diagnostic meaning |
| --- | --- |
| Saved destination and executing backend | `PrepareBackendPhase` validates the one-based saved USB index. A committed destination, a held startup chord or watchdog override can affect selection. On the ordinary path, it constructs the saved USB backend provisionally, then samples console detection. The XInput value returned for a USB connection is a USB-detection sentinel. The selector resolves it to the saved USB backend. A different detected console can replace the provisional instance. Inspect the primary backend on the ordinary dashboard and resolve its default mode row separately. |
| First USB attachment | Arduino-Pico `main()` calls `TinyUSB_Device_Init(0)` before Glyph setup. Device `begin` initializes the Pico device descriptor, registers CDC, then starts the RP2040 USB controller, pull-up and task IRQ. A host can see `2e8a:000a` (Raspberry Pi / Pico), a 75-byte configuration, CDC interfaces 0 and 1, and endpoints 81/01/82 while storage and display initialization run. |
| Switch registration | `init_primary_backend` appends the 86-byte descriptor to TUCompositeHID's buffer, updates the report-descriptor pointer/length and constructs NintendoSwitchBackend. Its constructor sets `0f0d:0092`, manufacturer `HORI CO.,LTD.`, product `POKKEN CONTROLLER`, serial string `1.0`, and calls HID `begin`. The final 100-byte CDC+HID configuration has three interfaces. Interface 2 is a gamepad HID with protocol 0 and interrupt IN endpoint `0x83`, max packet 64 bytes, interval 1 ms. It has no interrupt OUT endpoint. The eight-byte output report in the HID descriptor is distinct from the input endpoint. |
| Host configuration | TinyUSB opens class endpoints while handling a new SET_CONFIGURATION. Adding a descriptor later changes the in-memory configuration. A repeated SET_CONFIGURATION(1) for the current configuration skips the class-open path. The parent replay opens CDC only and stays mounted with HID unavailable. A host can also read the initial Pico descriptors and decline to configure the device. A late host in the replay can discover the final HID directly. |
| Scans and outputs | Normal core 0 services the bound primary backend. Switch scans SLOW and MEDIUM, waits up to 1 ms for HID readiness, then scans FAST and evaluates the bound game mode for this backend. Local input/menu activity can continue with zero USB submissions. A missing game mode or a menu that suspends it is a separate diagnostic condition. |
| Submission | An initially unready endpoint skips serialization/submission. On a ready turn, the backend maps buttons, hat, scaled axes and vendor byte, rechecks readiness and calls `sendReport(0, &report, 8)`. The pinned readiness predicate requires configured, unsuspended, a nonzero HID IN endpoint and no outstanding busy transfer. Submission can still fail on endpoint claim, copy or transfer. Its return is unused and the next normal frame samples again. A successful queue operation remains device-side evidence. |
| Physical receiver | The replay supplies host control requests and models the controller hardware and IRQ delivery. Only the real console can establish player registration and game response. If the final VID/PID and HID reach the console but input still fails, distinguish acceptance of this CDC+HID composition, endpoint/control-request behavior and the game input mapping before another firmware change. |

## Candidate correction and negative controls

Production changes are confined to the Mk6 build flag and `InitializeBootBackends()` in Glyph setup. After valid initialization returns a positive count, core 0 checks the **executing** primary backend. For Switch it drops the pull-up, waits 10 ms and restores it once. This point is after console detection and mode binding, before normal publication. It also covers a host that read the old VID/PID without mounting. A host that sees the new attachment can issue a bus reset, fetch the complete configuration and open HID. The pinned DCD controls the pull-up without allocating a new stack, IRQ or endpoint. The host supplies reset and configuration. Adafruit uses a 10 ms disconnect interval in its late-HID example. The candidate using this interval passes the owner's original Switch / Ultimate input trial. Physical timing remains unmeasured. ## Target ABI and historical attribution

The actual compiler is Arm GNU 12.3.0 for ARMv6-M Cortex-M0+ Thumb. Its target default is short enums, confirmed by compiler query and an object built with the exact release command. Size/alignment is 1/1 for the hat and 8/1 for the packed report. The button map occupies bytes 0–1, the hat byte 2, LX/LY/RX/RY bytes 3–6 and the vendor byte 7. The HID descriptor allocates 16 button bits, 4 hat bits, 4 padding bits, 32 axis bits and 8 vendor bits, without a report ID prefix. Target vectors include `55 15 01 94 a7 6c 57 00` and `aa 2a 08 94 a7 6c 57 00`. Compiling the same probe with only `-fno-short-enums` gives a four-byte hat, LX at offset 6 and an eleven-byte report. That counterexample explains the host fixture flag. The production target does not exhibit the mismatch.

The October 23 image at `1de243c7bada73ba85843018058b4f66a06acdda`, UF2 SHA-256 `a8a012e3d264d622a08ddfbe1f2e547c441c5406645203069e90314b4996e04b`, and the GOPT physical image use identical 86-byte HID descriptor bytes and pass eight bytes with ID zero in their linked code. The October send length is formed as 34 minus 26. GOPT loads 8 directly. Both have early core CDC attachment and later Switch HID registration. The later bounded wait and second readiness check change local progress when USB is unavailable. Neither reopens an unconfigured endpoint. The [October owner report](../../runtime_config/character_profile_menu/hardware_20261023/USB_Nintendo_Switch_owner_report.json) establishes the recorded Ultimate menu, selection/reboot, continued response and apparently normal controls. Kazuya was unselected. There is no descriptor trace or independently recorded console registration in that report. The reproduced enumeration defect predates GOPT. The corrected candidate now passes the owner's Ultimate input trial. The initial physical bus state was not captured, so attribution of that earlier failure to the reproduced enumeration race remains source-supported inference.

XInput instead constructs a vendor-specific XUSB interface and CDC, advertises `0738:4726`, and uses a Microsoft-compatible identifier. On a compatible Windows host, qualify controller detection and changing XInputGetState button/axis values. GOPT's physical XInput identity read is scoped to that diagnostic. Native Switch reception of XInput is outside the proposed support scope. ## Verification and limits

The exact program-only UF2 is 1,325,568 bytes, SHA-256 `de793f3469e8d88de31fb6f85d50bacd203b13928f1333ae5b291557c84b1518`. It contains 2,589 ordered RP2040 blocks covering `[0x10000000, 0x100a1d00)`. Its payload reconstructs the ELF-derived BIN plus final zero padding. LittleFS starts at `0x1017f000`. Address separation establishes what this UF2 supplies to the bootloader. Startup can still touch saved state, so each installation needs the current preservation baseline. The exact Switch translation-unit invocation, ABI probe, dependency commits and artifact digests are in the receipt.

All 22 current-host and focused commands passed across the run and provenance recheck, including both-ABI GameCube normal-poll report bytes, the terminal boot gates, input scans, 1,222,420 frozen native full-output replays, Config persistence, ProfileStore readback/recovery, package behavior and the 263-entry checker census. The initial build-input checks identified two stale inventories, which the frozen candidate corrects. The separate exact-base framework aggregate passed eleven checks before its adversarial self-test timed out; its cleanup/final fingerprint also exhausted the aggregate budget. The census passed separately. The prior GOPT run recorded the same adversarial timeout. There is no full aggregate PASS. See the [previous aggregate receipt](../gopt-qualification/integration/local-aggregate-summary.json).

Flash grows by 72 bytes to 650,556. Static RAM stays at 198,888 and heap capacity at 63,060. Both stacks reserve 2,048. Of 3,301 common functions, only the boot-backend helper changed linked call/frame shape (56 → 64 bytes). The added connect wrapper is eight bytes. The retained watchdog save/activation routes affected by that frame reach 1,968; detector 1,584; new wait at most 1,416 under the conservative startup assumptions. The inherited core 0 model still reaches 2,048 on legacy SET and 2,044 on lifecycle; both lie outside the changed frame. The core 1 envelope remains 1,068 of 1,152. These are bounded linked models. Runtime peak stack/heap and physical USB timing remain unmeasured.
