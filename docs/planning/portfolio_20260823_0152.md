## Largest current bottleneck

The largest bottleneck is **validation and mutation authority not matching the
live active table-source topology**.

`Ultimate.cpp` includes `UltimateIdentityRuntimeTables.hpp`; that header
includes `GeneratedRuntimeConfigBaseline.current.hpp`; macros then materialize
all 28 active `k*Table` arrays from those generated bytes. The active
`RuntimeConfigView` publication path is unchanged and source-owned, but the
generated baseline is still active table-content source. Current evidence is
internally inconsistent: the symbol-map packet correctly distinguishes active
table content from unchanged active-view publication, while baseline/install
packets and their checks also call the included header not included or
non-active. Write-capable tooling relies on that ambiguous classification. At
the same time, a stale checker census can coexist with an aggregate PASS and CI
does not run either gate. Until these facts are
reconciled, later source-owned generation work lacks a trustworthy fail-closed
boundary.
