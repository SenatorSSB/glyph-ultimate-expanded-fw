Status estimate: `CURATION_READY` for the bounded contract below; Curator retains

Objective: expose exactly which persisted profile the current Ultimate evaluator

Why this matters: it separates active evaluation from stored/readback/reference

### Proposed bounded design and fields

One const snapshot function binds the current **primary** backend's
`CurrentGameMode()` to the real `ultimate_mode`, verifies that Ultimate's actual
selected profile is exactly ProfileStore's active object, and reads the store's
latched ID/revision through a narrow const accessor. No raw pointer leaves the
firmware. Legacy embedded, absent, source fallback, unavailable context and any
object/correspondence mismatch produce distinct versioned neutral statuses and
no claimed persistent identity. A missing/invalid reference must not leak a
previous successful store activation as the current evaluator's identity.

Version 1 response contains: protocol version; request correlation token; explicit
status; current primary backend ID; current Ultimate row index only if the actual
mode's Config object is a member of the current Config array; its requested
persistent reference as separately labeled context; and, only for a proven active
persisted object, store incarnation, active ID, **latched active revision**, schema
version and SHA-256 correspondence marker. No arbitrary state or host identity is
invented. A host/platform label belongs in the external capture record.

The digest is SHA-256 of deterministic Nanopb `UltimateProfile` encoding of the
**actual active object**, using the candidate's pinned descriptor and domain/version
definition. Use a bounded streaming hash encoder, not native struct bytes or a
full stack payload. The host compares decoded/re-encoded profile bytes with the
same descriptor/domain; a hash of a raw record/header or unknown protobuf fields
is not silently equivalent. Keep raw readback hash separately. Digest failure or
inconsistent snapshot means unavailable, never a partially valid active claim.
ID/revision are necessary but insufficient to challenge wrong-object/schema
correspondence; the digest is required here. Incarnation namespaces persistent
IDs. Current directory revision/generation and Config generation do not identify
the latched runtime copy and are omitted from the active-identity claim; capture
Config/store observations separately and label their time/scope.

Compute the snapshot synchronously on the existing core0 service path outside
`UpdateDigitalOutputs`/`UpdateAnalogOutputs`. Do not latch duplicate identity at
selection, alter evaluator/selection logic, cache inferred Config identity, or
introduce periodic flash reads. Prove the tuple cannot tear across an activation
or Config replacement; return unavailable if stable ownership cannot be shown.

Provide one identity-only read service in Configurator and the currently running
XInput session. The smallest acceptable XInput extension is a finite bounded
identity request/response adapter on existing Serial, serviced from the existing
core0 loop/viewer ownership boundary. It must accept only this versioned identity
query and carry no Configurator SET, ProfileStore mutation, reboot, recovery or
generic dispatch capability. Use a distinct bounded frame/record discriminator
and preserve the existing viewer's complete 25-byte records and pacing; serialize
response writes at record boundaries. The host decoder must explicitly separate
viewer records from attestation responses and refuse ambiguous/partial data.
Configurator may wrap the same snapshot in a dedicated read command. Do not run
two independent readers over the same stream. No new USB interface, descriptor,
backend selection, scheduler, full Configurator instance, background worker,
hot reload, or persistence change is permitted. A version/length/token-bounded
wire contract must be frozen in the implementation's design/tests before coding
its handler; ordinary encoding details are engineering choices within this
fixed read-only scope. No general all-backend support is claimed.

This is a proposed small cross-backend observation extension, not an existing
capability claim. If existing stream ownership, viewer compatibility or timing
cannot support it truthfully with this bounded adapter, **stop for owner architecture
direction before implementing a wider transport/USB design**. A Configurator-only
fallback that always reports NO_ACTIVE_ULTIMATE does not complete the owner's
same-session XInput diagnostic objective.
