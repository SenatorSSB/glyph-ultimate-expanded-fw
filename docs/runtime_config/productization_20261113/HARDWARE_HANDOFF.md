## What to observe

| Step | Owner observation and retained evidence |
| --- | --- |
| **1. Cold boot** | On the same library and adapter, time power-on to the first usable GameCube input and to the first normal dashboard. Record profile count, full power removal, held buttons and About → Store / Backend / Ready / Screen (ms). Ready marks entry into report service. The external receiver establishes when output is usable. Compare normal boots with the owner's earlier approximate 1–2 s experience; record recovery or migration separately. |
| **2. GameCube first** | Confirm ordinary input at the adapter. Use the Profile menu to select the two eligible packages in turn. Record each displayed name and plate, its distinguishing input at the receiver, and which package runs after power cycling. For the physical selection chord, compare idle without a console and normal play with a polling receiver. Record a stall, missed report or unexpected switch. |
| **3. USB routes** | Check XInput and Switch USB separately. The exercised host examples are Lark (FGC, GameCube/Switch) and Wren (Split FGC, GameCube/XInput). Physical RF1 maps to LF1 on Lark and RF2 on Wren. Establish the expected indication at the receiver before switching. The direct running-profile identity service is available on XInput. In an approved session use the candidate's `tools/glyph_runtime_identity_tool.py` with `--context xinput`, the approved endpoint and an external session label. Compare backend, row, store incarnation, ID, revision, schema and digest. Keep direct identity on GameCube and Switch marked unverified; retain the actual dashboard and receiver observations for those routes. USB VID/PID, saved destination and executing identity are separate facts. |
| **4. Four guarded edits** | Switch away from the disposable target. UPDATE replaces its complete package; RENAME and REORDER must preserve its native wrapper. DELETE also requires that no backend saves it as its default and no protected reference breaks. For each approved edit take a fresh snapshot, issue once, correlate the receipt and check saved Config, directory, wrappers and unrelated defaults. Verify that the reclaimed pair can be used by a separately approved subsequent CREATE if physical capacity reuse is in scope. Use host results for interrupted-write coverage. |
| **5. Restore and record** | Check every per-backend destination, both backend selector fields, unrelated rows/RGB and original wrapper bytes against the baseline. Record any authorized changes and any remaining gaps. If a stored reference receipt prevents compaction, retain the refusal. An uncertain device mutation ends that episode. Keep its originals and stop before any retry, reconnection for reconciliation or compensation. |

## Operator and limits

The exact companion Senscope tool source is `7cdf301d618c5ba08fd7bd6ae5198a5bdcbe077f`. Read `tools/hardware-acceptance/productization/DISPOSABLE_CREATE.md` for preflight and optional test-pair preparation, and `tools/hardware-acceptance/productization/LIFECYCLE_OPERATOR.md` for backup and the four edits. Both operators use the same durable ledger. They were exercised against fake serial, and the CREATE path used the actual Mk6 candidate’s production storage implementation on emulated NOR. The standalone operator checks an exact plan, local UF2, endpoint identity and session-specific approval. Its descriptor contains the encoded DeviceInfo reply reconstructed from the retained ELF, the symbol address and the SHA-256 of the 88-byte symbol. DeviceInfo carries an eight-character build string. The local full-artifact hash and owner-reported installation custody provide separate evidence.

The edit operator checks each unaffected directory entry and wrapper, target readback, receipt and saved Config hash. Retain the pre- and post-edit raw Config and compare unrelated mode rows, RGB and default destinations field by field as instructed. A missing readback remains incomplete. A preflight failure before any write can be repaired on the host. Detailed instructions distinguish refusal, receipt-only and uncertain outcomes.

## If an observation fails

Retain the exact image, starting snapshot and observations. Fix the lowest affected feature branch and forward-merge into a new combined commit. Rebuild and identify ELF, BIN, map and UF2. Repeat affected checks, independent review, resource analysis and controller cases. Reuse evidence only for explicitly identical inputs and predicates. Firmware promotion and release require separate later decisions.
