## Options

A: rejected as public supported deinit/reinit. No tud_deinit/dcd_deinit/device.end API in pinned usbd.h/dcd.h/Adafruit device class. tud_init idempotently returns true without touching state. Not a reset.
B: detach/attach insufficient. Device.detach/attach cpp151/153 => tud_disconnect/connect usbd.c386–398 => DCD463–474 only clear/set pullup. No queue/class/endpoint/softwarestate reset. TinyUSBDevice.begin is NOT repeat-safe: descriptorclear removes CDC, CDC.begin sees validstaticinstance and does nothing, port then claims new softwareIRQ and adds duplicated sharedtrigger although tud_init noops. Direct dcd_init duplicates sharedDCDhandler. SDK irq_add_shared_handler206 consumes slot unconditionally; no deduplication scan. Never call these as generic reinit.
C: architecturally coherent if a recovery-only warm reset explicitly owns private reset seams and retains IRQ/OSAL allocations. Prefer preserving (not tearing down/reclaiming) exactly the alreadyregistered DCDhandler, taskhandler, tasktrigger, claimedsoftwareIRQ and initialized locks. Quiesce both USBCTRL and softwaretask IRQ on core0 in ordinary threadcontext, stop other USB users, detach, reset hardware/DCDendpointstate, flush device eventFIFO, invoke existing usbd_reset(0) and reset SOFpolicy, restore existing IRQ enable/clear oldpending at documented points, attach only after backend readonlystate/identity ready. Existing private usbd_reset465–472 resets allclassdrivers and device/mappings plus usbd_control_reset. Controlreset148–151 zeros complete controltransfer. Expose tiny repository-owned TU helper invoking that and tu_fifo_clear on existing queue; do not rerun queue_create/tud_init/PortInit. DCD helper can reuse existing393–428 body excluding sharedregistration and final connect, explicitly set _sof_enable=false (staticinitialized at55 but dcd_init does not reset it). Wholecontrollerreset and DPRAMclear thenEP0/noncontrolreinit produce consistent hardware/software restart; isolated peripheralreset alone is forbidden.

C is NOT a supported upstream deinit API. It is a new bounded repository-owned lifecycle adaptation. Need deterministic copied/patched TU generation, originalobject exclusion, exacthashes, positive/negative tests and freshreview. Do not edit installedframework. In normal mode all original codepaths and callcounts must remain identical. If full teardown chosen instead, privateport taskIRQ number/callbacks must be exposed, disabled/cleared/removed/unclaimed; DCD handler removed; queuecriticalsection freed/recreated; class/descriptor lifetime solved. This is more invasive than preserving infrastructure and not recommended first A/B.

D: not necessary for firstcandidate: manual RT2 already advertises only CDC from existing begin and no gameplaybackend constructors execute. Retain current2E8A:1092 Configuratoridentity/protocol; no VID/PID or descriptorredesign authorized by this audit.

## Follow-up exact reset invariants

CDC ITF_MEM_RESET_SIZE is offsetof(cdcd_interface_t,wanted_char), cdc_device.c86. Therefore wanted_char AND line_coding are retained by cdcd_reset; default115200 is an init invariant, NOT a warm-reset invariant. Endpoint/interface/line_state state precedes reset boundary; RX/TX FIFOs clear. Do not claim coldstack reset using this helper. Read-only management uses existing CDC data protocol and need not change baudcoding. XInput init/reset are both noops, audited at dependency211–215; no NULLobject dereference in reset. Its static pointer remainsNULL on explicit manualroute where no backend constructor ran.

No separate queued-SETUP counter or setupwork counter exists in this exact usbd.c. Setup event payloads live in queue; queueflush discards oldpayloads, usbd_control_reset zeros complete request/buffer/length/total/completioncallback state. Configuration reset includes all compiled driver reset callbacks then device-state clear and FFmapping rebuild. The queued event storage itself need not be bytezeroed for logical FIFOempty invariant; if new test asserts memoryzero instead of FIFOempty, that is not source-faithful. tu_fifo_clear implementation must be checked for lock behavior by implementer before direct helperuse.
