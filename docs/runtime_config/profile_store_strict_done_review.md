No production GC or required GC fault suite exists. **Class: source change plus evidence and owner hardware. Smallest next action:** separately authorize the missing checked capacity/admission surface and protected-union accounting, then produce bounded full-storage/GC evidence and target geometry/interruption evidence. No docs-only claim can close this.

**B2 — observable checked sync/close and unknown publication outcome.** Requirement D94–115,221–225,330–337. Production `LittleFsDirectoryStorage::Write` (`ProfileStore.cpp:113–120`) checks bytes written, calls void `File.close()`, then returns the earlier write status; Read likewise discards close outcome. The adapter has no sync/close interface. `Persistence.cpp:183–205` closes without a result, verifies staged bytes, rotates/renames, and returns false on rename failure even if the real primitive could have committed before lost acknowledgement. The separate pinned-LittleFS harness checks `lfs_file_close` itself (`littlefs_harness.cpp:39–46`); that is not the Arduino production path. Retained fault tests and successful hardware CRUD do not establish the required checked sync/close and interruption guarantee. **Class: source change or an actual equivalent-primitive proof, then owner hardware. Smallest next action:** authorize a same-mount checked adapter (or independently prove an equivalent primitive satisfying every named outcome), add operation-specific failure/lost-ack tests, and retain target interruption observations. **B3 — profile-changing chord hot-switches.** Requirement D52–55,124–129. `src/core/mode_selection.cpp:211–217` changes current_mode_index and calls set_mode immediately when held buttons match; `114–122` invokes `profile_store.Activate` and passes the new active object to Ultimate. `config/glyph/common/src/config.cpp:290` calls this during ordinary loop. **B4 — transaction contract is incomplete.** Requirement D100–108,197–199,326. Backend350–351 splits request_token into low32 token/high32 caller-provided digest; it does not compute/verify a digest of the request. `BeginMutation` at305–309 compares only these supplied values, so changed payload/name/operation under identical token bits is not recognized as different. Most importantly, reference SET at385–423 saves Config but persists no token/digest/result; QUERY at425–426 consults only the directory's result at `ProfileStore.cpp:338`. A lost SET_MODE_REFERENCE response therefore cannot be reconciled through the required equivalent Config transaction identity. Smallest next action:** implement authenticated request identity and durable Config-reference outcome/query, and fence/reconcile uncertain commits before further mutation. The retained CREATE lost-response query PASS remains valid for its tested case; it is not this complete contract.
