## Decision and rejected alternatives

Use native schema **5**, encoding **1**, engine ABI **1**. Keep failed experimental4 unsupported; V1–V3 interpretation remains unchanged. Add one `UltimateProfile.native_payload` bytes callback at protobuf tag8. Existing legacy fields2–7 must be absent for schema5. Native profiles are ProfileStore-only; main Config contains a stable ID plus a small expected-engine discriminator, never native bodies. Existing operations, checked transaction identity, directory64, record kind1/header32, record/payload4096 bounds, roots, reserve, corruption isolation and boot-bound selection stay in place. No new command, transport, backend, hot switch, filesystem, timing or scripting facility.

Do not append large fixed native arrays to `UltimateProfile`: it repeats in three Configs×two embedded profiles, store active/candidate, request and response. Do not repurpose coordinate bytes or legacy routing slots as hidden bytecode. Do not union unrelated legacy protobuf fields under a new meaning. Do not build another SOCD, coordinate solver, general expression VM, dynamic allocator, program cache, global input ownership scheme, or forced-direction subsystem. Current coordinate modes and finite all/any/none machinery suffice (`Ultimate.cpp:693–775`, evaluator conditions/table selection); the missing work is explicit input domains, generic activation/composition and an owned native payload/view.

## Frame boundary and reuse

Add a protected virtual `UpdatePreprocessedOutputs(context, outputs, backend)` to ControllerMode; its default calls existing digital then analogue methods on context.post. `ControllerMode::UpdateOutputs` keeps original reference, creates remapped snapshot, calls existing HandleRemap once, copies post snapshot, calls existing HandleSocd once, and invokes hook. Context has const original/remapped/post references; its lifetime is one call. Ultimate overrides hook only for valid native or native-unavailable dispatch; all other paths use the default unchanged. This adds two bounded InputState locals; measure actual stack. No per-function or per-direction SOCD and no altered `_socd_states` ownership.

Native evaluation pins one immutable active-program pointer and generation at frame start. Evaluate finite early predicates; obtain eight LS/RS cardinal activation booleans through explicit post-input/early-role direction references; reuse `UpdateDirections` and its accepted opposing-input tie behavior; evaluate late predicates that can observe resolved direction signals; select table; OR digital contributions; apply the one existing-style digital post-mask; produce direction/Dpad outputs; resolve analogue effects by validated priority; run preserved Nunchuk tail. This is one coherent evaluation rather than the existing repeated legacy digital/analogue role calculation. Profile-data tokens contain the physical IDs; native evaluator never switches on Glyph slots.

Direction-source records are data adapters for the existing coordinate caller arguments and `EffectPoint` transformations, not preprocessing or a new stick solver. Base LS and RS sources reference only post-SOCD logical inputs or early roles. Additional sources reference validated early/late predicates or derived directions. They map boolean negative/positive pairs to the exact existing `UpdateDirections` left/down preference. Source-faithful RF6 cancellation is represented by predicates `down&&!up`, `up&&!down`; source-faithful LS horizontal cancellation similarly uses predicates. No history runs here. Duplicate post-input references across output domains are legal. Ambiguous cyclic references and duplicate source IDs are rejected.

## Finite encoding and resource contract

All integers are explicit little endian. No struct memcpy wire format. Native body has no enum ABI dependency. Max body **3336**, exact schema5 protobuf wrapper **3341** (`08 05 42 <len> <body>`), record **3373**. This includes maximum section counts and token-pool occupancy. Reject larger native body, mixed legacy/native fields, duplicate native tag, unknown encoding/engine, trailing/short bytes, reserved bits/nonzero unused union bytes, invalid dimensions and every invalid reference before activation.

Header96 bytes: magic GNP5@0; encoding u16@4=1; engine u16@6=1; total u16@8; condition_count@10<=96; early_condition_count@11<=count; source_count@12<=8; rule_count@13<=32; binding_count@14<=32; effect_count@15<=16; default_table@16<28; baseLSsource@17; baseRSsource@18; Dpad flags@19<=7; mode_gate u16@20; LS-digital-enable gate u16@22; RS-digital-enable gate u16@24; Dpad gate u16@26; preprocessing SHA256@28; conversion source/provenance SHA256@60; token_count u16@92<=768; reserved zero@94.

Sections follow in fixed order:

|section|max records|wire bytes/record|maximum bytes|
|---|---:|---:|---:|
|all28 tables, nine raw x/y pairs each|28|18|504|
|condition header: explicit ID u8, counts packed u16|96|3|288|
|shared condition-token pool|768|2|1536|
|direction source: ID u8, left/right/down/up token u16×4|8|9|72|
|table rule: unique priority u8, table ID u8, gate u16|32|4|128|
|digital binding: gate u16, button mask u16, winner-table u8, flags u8|32|6|192|
|analogue effect|16|32|512|
|digital post-mask: gate u16, set u16, clear u16, flags u16|1|8|8|
|header|1|96|96|

Conditions retain all<=2, any<=4, none<=9; packed counts occupy2/3/4 bits, remaining bits zero. Each record's tokens occupy the next pool segment; preparation computes and validates offsets once. Global768 cap is deliberate and independent of per-condition maxima; exhaustion returns invalid/resource error before any publication/write. IDs are explicit, canonical ascending, dense1..count. Role dependencies only to lower IDs. Early predicates cannot depend on direction/output/winner signals. Late predicates can depend on already resolved directions but cannot feed the two base direction sources. Bindings cannot read output bits. Analogue gates may read the resolved digital bits after post-mask. Winner-dependent binding/effect selection is an explicit optional table ID0..27;255 means no winner restriction, so ordinary A remains independent.

Token u16 vocabulary:0=false;0xffff=true; kind0x0000+ID1..60 original physical;0x1000+ID remapped/pre-SOCD;0x2000+ID post-SOCD;0x3000+ID condition1..96;0x4000+ID1..8 resolved cardinal activation;0x5000+ID1..12 final digital button carrier (analogue-effect gates only). All other tokens fail. Numeric bit identity is resolved with existing source accessors, not assumed from enum spelling. Constants never name a physical control.

Effect32 bytes: target u8; priority u8; intrinsic activation u16; independent profile gate u16; direction source u8; coordinate mode u8; table0/table1 u8; coordinate union18 bytes; winner-table u8; flags u8; reserved u16. Existing selected/table/fixed/inline coordinate modes remain; trigger targets use one union byte value and zero the remainder. Target LS/RS/triggerL/triggerR/both-sticks; both-sticks conflicts with each individual stick. Reuse mode gate to choose table0/table1. Flags are only invert-extra-gate and skip-when-LS-route-bypass; reject unknowns and illegal combinations. Trigger effects additionally require final trigger digital bit via their intrinsic activation; they therefore honor Stage-C digital clear/set. No new coordinate mode.

Digital mask limited0xfff; all bindings OR without consumption. Optional winner filter is explicit; bind flags currently zero. Post-mask applies clear then set after OR, with disjoint set/clear, one gate and one inversion flag, matching existing finite Stage-C mask. This is sufficient for arbitrary accepted V3 mask variation without introducing a multi-layer digital override system. Dpad routing remains the existing three flags: route LS directions, center/bypass LS analogue candidates, suppress LS digital directions. Center coordinates are an ordinary effect using any currently supported coordinate mode; the bypass signal independently disables flagged LS candidates even when those coordinates are not centered. Digital LS suppression, routing and analogue bypass remain independent flags.

Table rules use unique priorities1..255 and choose the smallest; none -> explicit default. Coordinate/trigger effects also use priorities1..255 and choose the smallest separately in each overlapping target conflict domain; reject equal priorities for overlapping targets even if gates appear mutually exclusive. Array ordering is never precedence. Analogue initialization uses existing UpdateDirections min28/neutral128/max228, matching suppressed legacy base effects. Native presets may configure ordinary base-table effects. Per-frame conditions and bool/axis values are bounded; no parsing/framing/varints/bounds inference/file access/writes/heap in polling. Validated typed views have precomputed section/pool offsets and fixed-width scalar readers. Scalar access to an immutable validated table is evaluation, not parsing a payload frame. Canonical bytes themselves are the active semantic program; do not duplicate their tables into a second compiler structure.

At most one owned active body and one owned candidate body, each3336, plus bounded metadata for condition/source offsets, identities and generation. Inactive bodies remain on flash. Request/response/profile wrapper grows only the ARM8-byte callback, never3336 per Config copy. Borrow existing synchronous receive/read-wire buffers for transient incoming/readback payload leases; do not retain them. Exact metadata C++ ABI/stack/native build measurements remain mandatory before M1 final acceptance; total RAM is independent of profile count.

## Ownership and callback integration

Native `UltimateProfile` is a small schema5 wrapper whose callback's argument identifies a bounded native lease/owner, never a raw pointer silently copied into Config. Read/decode entrypoints must explicitly install the appropriate native decode handler or reject handler. A bounded protobuf presence scan outside polling identifies exactly the profile schema/native field and nested callback path, rejects duplicate tag8/mixed native+legacy before decode, and supplies an immutable slice of the existing8192-byte Configurator frame or existing4128-byte record-read wire. The callback consumes that exact field and binds synchronous encoding to that lease. Do not infer buffer ownership from Nanopb private state or silently skip callback bytes.

Request ownership lasts from completed RX through decode, request-identity encoding (token restored), semantic validation and transaction/write. Explicitly release/invalidate the incoming native lease after its last identity/transaction use and BEFORE response encoding, because the current response encoder reuses that incoming frame. A READ response native lease must refer to the distinct record-read wire or candidate owner, never the incoming frame. No asynchronous use or reuse of incoming frame while its incoming lease remains live. ProfileStore record read leases live only until the next read; activation validates/compiles/copies to candidate-owned bytes before any next read, and READ/DUPLICATE encodes synchronously before releasing the lease. Create/Update encodes from the immutable incoming frame into the distinct existing write-record buffer. Verify actual call graph for overlap; if an existing caller requires nested read while a leased read payload is still used, copy into the one candidate owner before nesting. No new unbounded/request-specific profile cache.

Publication copies fully validated candidate body+metadata into active owned storage before publishing native pointer/generation on the owning initialization path; no polling/hot-swap concurrently. Update/read/health/duplicate never alter active owner. Active wrapper callback is rebound to the active owner, not shallow-copied from candidate. No Config gets native callbacks; Config/Persistence/legacy migration/SET_CONFIG decoders reject any native field in embedded profiles, including schema1+tag8 whose default callback would otherwise skip it. Clear transient decode callback pointers before any accepted Config copy/persist. All current embedded V1–V3 bytes and fallback remain supported.

Adding a callback can remove generated `UltimateProfile_size`, request/response/Config size macros. Audit every consumer, especially `RuntimeProfileDigest.hpp` (`stream.max_size` currently macro), wire/COBS encoders, schema descriptor guards, Config persistence and host tools. Replace only affected bounds with source-backed limits (profile4096, actual enclosing accepted limits), not SIZE_MAX for bounded frame encoders; existing streamed request identity uses SIZE_MAX and hashes known fields synchronously. Both enum ABIs and production fresh descriptors are checked. Native full wrapper3341 is below both4096 admission and4056 single-storage-charge cliff.

## Activation, failures and context integrity

Add `GameModeConfig.ultimate_profile_engine` at fresh tag205, uint8 storage,0 legacy/default,1 native5. Checked SET_MODE_REFERENCE derives and commits the expected engine from the selected valid record along with ID; SET_CONFIG validates expected engine against native/legacy selected record, rejects unsupported/mismatched claims, and never embeds native bodies. This small field is necessary because a bare ID loses requested-kind knowledge when record/directory/root is missing. Default zero preserves all old Config behavior.

For each stable ID, reject Update across legacy/native kind boundary; ordinary V1↔V2↔V3 updates retain existing acceptance. Native is a new Create ID; Duplicate preserves kind. This avoids prior legacy revisions being revived under a native reference. A source-backed native expected-engine annotation, not ID-bit overloading, persists through directory loss. Previous-revision recovery may activate only a valid same-kind native record whose bound preprocessing matches. A schema5 record with unexpected legacy annotation fails closed when known. Missing/corrupt/unsupported record, invalid root, read-only recovery, context mismatch, bad compilation or known kind mismatch under expected native yields explicit NativeUnavailable. It cannot call default legacy Ultimate even if previous active pointers exist.

NativeUnavailable emits buttons0, sticks128, triggers0, including all clicks/directions/mod bits; no Nunchuk or other legacy tail applies in this failure state. Existing recovery/configurator initialization authority remains unchanged; no new normal-mode writes. Native mode reinitialization invalidates the old native handle before attempting a new selection, and only successful full publication enables outputs. Legacy expected-engine0 and versions1–3 keep historical source fallback exactly. If current Config itself is corrupt, existing Config recovery remains authoritative; no valid native-session claim is made.

Preprocessing digest canonical domain `Glyph.Native.Preprocess.v1\0`, mode ID as little-endian u16, ordered remap count u8 and pairs (physicalID u8,logicalID u8), ordered SOCD count u8 and triples(dir1 u8,dir2 u8,type u8), each validated finite enum/ID; do not hash struct padding, profile ID, mode name or unrelated fields. Ordering matters because remap first-source and ordered SOCD pair execution matter. A package includes the actual context and digest; admission can store it without changing Config, but activation requires exact current row match. Profile update alone never changes preprocessing. Reject unsupported context policies rather than guessing.
