## Priority 1: end admission capacity workspace before the GC write branch

`ProfileStore::Admit` (source1346) first calls CollectGarbage, then declares `auto c=Capacity()` and computes the unchanged formula. Exact ELF10027dd0 pushes24 and reserves88 BEFORE BL CollectGarbage10027dde. Its112-byte frame therefore contains a dead future CapacityInfo return slot during GC metadata removal.

Preferred realization: keep Admit's CollectGarbage call/error branch first, then call a private noinline `EvaluateAdmission(bytes,records)` containing precisely the existing Capacity call, block-size test, FileCharge arithmetic and comparison. This creates a real sibling phase boundary: the capacity workspace does not exist during the earlier GC call. No capacity call or arithmetic is moved before GC; error precedence and actual storage sequence remain identical. The helper's frame exists only after GC has returned. Expected Admit retained frame16–24 instead of112, saving88–96 on GC/remove paths; actual O3/final-ELF measurement must replace this estimate. No added static storage, no changed reentrancy premise and no capacity cache.

Alternative only if compiler/proof favors it: construct Capacity's returned POD directly in a fixed per-Admit CapacityInfo scratch after successful GC. Charge actual ARM size (expected64) inside current2104-byte total-RAM headroom. Reset by direct returned-POD construction every call; don't use a one-time initialized call result or retain old c on failure. The current public Capacity() implementation already initializes defaults/reserve and fills its result, including early-return outcomes. All existing formula operands/order/results must remain literal-equivalent. Static lifetime requires the single-core, synchronous/non-reentrant premises below; the noinline phase alternative avoids those new premises and is preferred.
