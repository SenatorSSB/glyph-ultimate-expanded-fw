## Finite lifecycle, cancellation and custody

One process-lifetime State owns one fixed serial queue, buffer and all native resources. Its allocation is deliberately never deleted; it is reclaimed by controlled process exit. At most one read is outstanding, with maximum3 submissions/reports. A separate monotonic5-second observation deadline starts before registry/open work. Successful completion requires three fully decoded reports within that bound. Partial reports remain evidence of a stopped session, never qualification PASS.

The I/O timer requests asynchronous pipe abort at most once and arms a1-second grace before any fallible abort/log operation. SDK synchronous abort waits for completion and has no finite deadline, so it is not used. If cancellation does not drain, the complete State, pipe/interface, buffer, callback target, queue and journal remain retained until process exit, and the final outcome is UNCERTAIN_STOP. Late callbacks see finished and perform no resource or journal access. All exception paths preserve that ownership; the independent main-thread8-second process watchdog exits without destructors if the I/O queue/API stalls. A future wrapper must also impose a10-second external process deadline. OS scheduling/abort-completion guarantees are not invented; the external watchdog is a process bound, not a USB cancellation guarantee.

Settled cleanup is queued after the current completion block returns. It cancels the timer, releases the pipe, calls interface destroy once, clears interface/data, then records settled_cleanup and flushes/closes the journal. This preserves resources through the callback epilogue. No pending destructor/delete path exists. Uncertain cleanup deliberately does not call destroy or close the referenced journal before exit. `destroy` idempotence and service ownership are SDK contracts (Object.h79–84); unknown kernel/API behavior remains a runtime gate.

Output files are new O_EXCL0600 files; session labels are bounded safe characters. Raw and decoded rows share sequence and monotonic host-receipt timestamps. These are host times, not device sample times. The successful native live source path emits empty stdout and stderr `COMPLETE: bounded host preflight; hardware acceptance NOT_CLAIMED` plus newline. Stopped settled paths emit the corresponding `STOP:` line; argv failures/watchdog have distinct STOP messages. These exact source-derived expectations are pinned in build_environment.json, not asserted as observed live stdout. Root must require process exit0, no timeout, custody flush/close and the complete journal; an end row alone is insufficient if final close fails.
