## Installation and lifecycle facts

The exact setup has one initialize_backends call. That routine performs at most an initial default-backend installation before detect_console and a final backend installation afterward. Its primary initializer pointer is the source-defined init_primary_backend; there is no assignment to a substitute initializer. Glyph's secondary override delegates to the default secondary initializer, which adds only B0XXInputViewer for DInput/XInput. It creates no second physical console backend. After setup returns, select_mode changes the requested persisted destination and reboots; it does not replace communication backend objects in the current boot. set_mode assigns controller/keyboard mode pointers and does not instantiate console backends. The mode-destination selector is installed after initialize_backends returns. Thus ordinary loop persistence cannot occur while detector callbacks are being installed or removed. Legacy watchdog SaveConfig inside initialize_backends is also after final initialization and after detection returns; the same GPIO exclusions apply there, though its foreground prefix is a separate accounting obligation.

Do **not** assume a USB-only default row: is_valid_usb_default_index checks count/index, not the selected row's backend type. The semantic validator uses that same index check and does not add a type restriction. An admitted Config can therefore create NES as the initial so-called USB default, then detect/reinitialize another physical backend during the same setup. The proof below covers those histories explicitly, rather than relying on a pristine/default-only initialization history or a no-physical-replacement premise.

## Priority0 implies raw ownership of the sole enabled pin

NesConsole constructor adds raw IRQ mask bit10 before setting IO_BANK0 priority0. Once priority0 has been set in this source, no later actual call clears raw bit10. This statement includes unusual physical-default replacement histories:

* NesConsole destructor disables latch10 but passes **port.data_pin8**, rather than latch10, to gpio_remove_raw_irq_handler. Exact destructor10005cda–10005ce2 constructs1<<data_pin. The linked gpio_remove_raw_irq_handler_masked10041f20–10041f3a removes the shared handler and clears precisely the passed raw-mask bits; no assertion branch or repair of the mask is emitted. Therefore it clears bit8 and leaves bit10 set. This is an exact existing behavior used for accounting, not a proposed source repair or a claim that this cleanup is otherwise correct.
* SnesConsole constructor raw-claims data8, and its destructor removes data8. Neither clears bit10. A later NES constructor sets bit10 again. No other actual raw-mask removal caller clears bit10. There are at most the bounded initial/final physical installs above, and no runtime console-object replacement afterward.

Consequently, whenever GPIO could run at priority0 during ordinary persistence, the only potentially enabled post-detection event pin10 is raw-owned. gpio_default_irq_handler10041fbc reads enabled INTS and checks raw_irq_mask before acknowledging/calling the callback. At1004201a–1004201c its nonzero raw bit branches past the callback call at10042030. The Arduino dispatcher and CoreMutex constructor are unreachable from all enabled ordinary priority0 GPIO events. Its remaining scan has own40 bytes and no executed child call. A stale NVIC pending activation without enabled non-raw events also cannot enter the callback. Clock9's event mask is disabled after detach, so an edge there cannot supply a counterexample.

This is stronger than claiming that the default shared handler itself is uninstalled: it remains installed after detection. It is also stronger than assuming that SNES always has priority0x80: an initial NES row can leave priority0 inherited by final SNES. In that history bit10 remains raw-owned, so the112-byte default/dispatcher subtree still does not execute. If no NES constructor has executed, IO_BANK0 stays0x80; a final SNES latch10 can enter the112-byte subtree (its own raw mask is data8), but it cannot preempt another0x80 USB/alarm/SIO activation. SysTick0 may instead preempt that GPIO activation, yielding the smaller204-byte alternative from the earlier report.

The128-versus0 priority split and raw-mask invariant cover arbitrary admitted Config backend/default selections in this exact initializer graph. They do not rely on what a user is likely to select. They do rely on the pinned Mk6 pins and exact existing raw-mask cleanup. A later cleanup change that clears bit10, new GPIO callback/event registration, mutable pinout, new backend lifecycle or NVIC priority writer invalidates this amendment and requires reassessment; in particular, a corrected NES cleanup plus physical-NES-default→SNES history could restore the earlier456 conservative union.
