## Producer state with a bounded valid response tail

HandleGetConfig validates the saved Config, writes CMD_SET_CONFIG and raw Config protobuf to its persistent packetio::COBSPrint _out, then returns _out.end(). The PacketIO end method sends its final COBS buffer chunk, writes delimiter0 to the base stream, resets the counter and returns. It does not call ProfilePacketWriter.finish or CoordinatedCdcStream.txSubmitted(). There is no _txSubmitted flag: txSubmitted is a separate FIFO-drain query used by the Profile packet writer.

CoordinatedCdcStream::write **does** call serviceTx after accepted writes, including the legacy end writes. This does not imply drained TX. serviceTx runs the USB task then attempts tud_cdc_n_write_flush under its Guard. If IN remains busy, endpoint claim fails and queued TX remains. The function returns accepted bytes when sent==length; it does not wait for txSubmitted/host completion. ProfilePacketWriter.finish differs by looping on txSubmitted, but the legacy response bypasses it.

Choose an enumerated, ready CDC connection with DTR asserted, no suspend/reset, and host scheduling that drains earlier response chunks. At the final COBS buffer, make the FIFO empty and IN idle. Let its length L be1..255 (the COBS buffer's exact maximum), and withhold host IN transaction/completion once this final write arms an IN packet. tud_cdc_n_write accepts the chunk into TX FIFO256; at>=64 bytes it automatically flushes one bulk packet64, while for a smaller tail serviceTx arms the tail packet. In all cases IN is busy afterward. Any remaining final chunk bytes fit the FIFO, and the final delimiter0 is accepted as at least one queued byte behind that busy transfer. Maximum tail pending after a64-byte drain is192. serviceTx attempts cannot complete an IN transfer the host has not completed. Therefore all final writes and end can successfully return while IN busy and FIFO count>0, without any2s writer timeout or partial COBS state. This construction works even when the final tail is short: the delimiter itself supplies the nonempty FIFO.

The host may send the next valid framed ProfileStore request on the independent OUT endpoint before consuming the old response tail. Source has no request/response-idle gate requiring old legacy TX to drain. The host can already know the target/profile/token from earlier state; neither malformed input nor arbitrary memory corruption is needed. Subsequent SkipToNextPacket/_in.next only advances the RX packet lifecycle. ReadByte/ReceiveProfileStore/fillRx service USB task/RX operations and may rearm OUT, but cannot invent the withheld IN completion. A task with no IN completion event does not call the IN-transfer callback just because TX is pending.

Choose the subsequent valid UPDATE/DUPLICATE request with liveness_trace=false and no error response before execution. With strict diagnostics enabled, TraceProfileStage returns immediately for this flag and does not invoke WriteProfilePacket/finish. With strict diagnostics disabled it is an inline no-op. Thus no optional receive-stage diagnostic drains the FIFO. Previous ProfileStore responses that ran finish may have different predicates; the witness specifically uses the legacy response. The original _profile_tx_needs_sync flag is false after a normal session; no extra delimiter-repair path is required.
