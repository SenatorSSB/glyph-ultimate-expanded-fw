## Fixed wire contract

Exactly one operation: GET_SNAPSHOT. Request16 bytes: offsets0–3 **d7 47 4e 4d** (D7/G/N/M);4 version1;5 opcode1;6–7 LE length16;8–15 nonzero LE64 opaque correlation token. Response160 bytes: same magic/version, kind0x81, LE length160, echoed token. No arguments, reset/start/stop/clear/write/profile/memory/address/length/firmware control operations. Magic check against current source protocol declarations finds no matching command; existing identity magic is a5/GRI. Individual d7 bytes in bitmap data are irrelevant. Arbitrary payload/token bytes can contain either magic: ownership rules below, not supposed byte uniqueness, prevent command injection. Recheck collision against final source and negative fixtures.

|---:|---:|---|
|0|16|Fixed framing/token above|

|17|1|Actual backend ID2, XInput only|

All multibyte integers LE; encode fields explicitly, never memcpy a padded C++ struct. Each20-byte statistic is five u32 words in the displayed order; sum is an unsigned64 represented by low/high words. Empty statistics encode all five words zero. Count saturates atUINT32_MAX; sum saturates atUINT64_MAX. Min/max continue updating after count saturation, sum continues until its own saturation. Independent sticky saturation flags prevent exact-count/mean claims. No silent wrap. No histogram, floating point or dynamically sized data.

Each16-byte stack observation is observed/conservatively occupied bytes u16, deepest sampled-SP-used bytes u16, completed scan generation u32, max scan-chunk elapsed microseconds u32, flags u16, reserved u16=0. No stack address/raw bytes or arbitrary memory content crosses the wire. Exact validity/source/timer/stack bit assignments are frozen in JSON; all unspecified bits and reserved words are zero. A host rejects unknown version/kind/length/bits rather than guessing a newer protocol.

COMPLETE requires at least one valid frame/activation, completed16-sample calibration, stable complete scans on both cores, valid source label and matching actual native generation, and no saturation/pending/integrity fault. PARTIAL covers absent samples, incomplete scans/calibration, unstable mailbox read or saturated count/sum. INVALID covers stack/bounds/entry/active-generation integrity faults or expired measurement window. Recovery-previous activation is labeled explicitly and can still be a valid successful activation. Raw retained numbers may accompany INVALID, but are not accepted measurements. Bad request headers/version/opcode/length/zero token never produce a response. These are three outcomes of the one read-only snapshot, not additional commands.

Source flags mean CLEAN_COMMITTED_SOURCE and FULL_SOURCE_SHA_PRESENT only. Build script derives the exact40-hex Git SHA from a clean committed source, emits20 constant bytes, and fails dirty/unresolved source. SHA label is not a device cryptographic attestation or its self-hash. Do not put it in identity digest/status bytes. Exact ELF/UF2 custody plus operator/device packet still establishes artifact correspondence.

## Single-owner RX/TX mechanics

Existing `runtime_identity::Service::Poll` remains the only Serial reader, noinline, called on core0 after complete backend/viewer reports. Existing valid identity requests/responses, status semantics, admission72+32 and return-after-response behavior remain unchanged. `RuntimeIdentityWire.hpp` is allowed **only** one const state query `HasPartialFrame() const { return _used != 0; }`. Existing fields/layout/constants/Consume/Expire/DecodeRequest/EncodeResponse/statuses remain byte-exact. No generic parser rewrite or shadow copy of identity state.

Call original identity Expire(now) at Poll entry. It owns its partial frame, including opaque body bytes that resemble diagnostic magic. Only when it is idle may diagnostic prefix matching begin. Prefix bytes d7/G/N/M contain no a5; one to three matched diagnostic prefix bytes do not own the stream. On mismatch, discard that tentative prefix and reconsider the current byte: a5 goes immediately to the unchanged identity parser; d7 restarts the diagnostic prefix; other bytes go through the existing identity parser (which remains idle). Do not swallow a valid identity start after a stray d7 or truncated prefix. Once **all four** diagnostic magic bytes match, diagnostic RX owns the remaining12 opaque bytes; embedded a5/GRI is data. Collect exactly16 bytes, validate, then release ownership. Malformed complete diagnostic frames consume that fixed frame and emit nothing. Both partial ownership windows expire at250ms using unsigned elapsed milliseconds, and the current byte is reconsidered after expiration. An old partial identity frame continues to use its original timeout/resynchronization rules unchanged.

At most32 wire.read calls per Poll and at most one response. A valid diagnostic frame becomes a candidate for the current Poll only: preserve its16 bytes/token in the fixed parser buffer; no response queue. Continue within the remaining32-byte budget so a completed identity request takes priority. If identity completes, preserve its original admission/response/return and discard diagnostic candidate. If identity remains partial, unread RX remains after budget, another diagnostic candidate arrives, or ownership is ambiguous, discard diagnostic candidate. Do not overwrite the first candidate token; additional commands in the same Poll cause diagnostic drop. Retry is a host concern. No scanning ahead beyond32 to find priority traffic.

Only after normal RX priority processing, emit diagnostic when primary backend remains XInput, no identity partial/unread RX remains, no prior response, availableForWrite>=192 (160+32 reserve), and at least1000ms since last successfully admitted diagnostic response (first response allowed). Rate-limited or TX-busy requests are silently dropped, with no BUSY packet, wait, queue or extra command. No unsolicited output. Source expiration/error status may still return a fixed INVALID snapshot; malformed requests never do. Treat a short write after admission as an unexpected transport failure in host evidence; never retry remaining bytes in a blocking loop. Verify actual TinyUSB admitted-write behavior during source review.

Viewer code is unchanged: `B0XXInputViewer.cpp` requires32 TX reserve, skips while `_clock<5`, then writes25 ASCII/newline bytes and resets. Preserve exactly this source behavior (avoid claiming a mathematically different five-frame cadence). It runs before observer service. Host decoder recognizes fixed160 diagnostic frames, fixed72 identity frames, and intact25-byte viewer records without interpreting opaque token/payload magic as a new frame. Adversarial fixtures must cover interleaved messages, partial-prefix timeout, stray d7+a5 identity, full-frame embedded other magic, bad version/length/token,32-byte budget, TX reserve, rate drop and identity priority. Existing identity vectors remain unchanged.

## Timing and native gating

Use existing SDK time_us_32 (one-microsecond timer domain) without timer/alarm/IRQ/SysTick/clock changes. Begin/End raw native interval encloses the **single** ControllerMode::UpdateOutputs body: existing remap, SOCD, resolved context, native evaluator/refusal work. Input scan, USB readiness, backend serialization, stack scans, serial and metric-record stores stay outside that raw bracket. IRQs remain in their normal state; elapsed deltas include any preemption/stalls and quantization. No CPU-exclusive/cycle/WCET claim.

One smallest declared interface dependency: public const virtual `ControllerMode::DiagnosticNativeGeneration()` returns0 by default; Ultimate override returns its actual nonzero generation **only** when ActiveEngine is NativeAbi1 and its current view is owned, valid, published and matches the stored generation. Never gate from requested engine/profile alone; NativeUnavailable and legacy return0. The predicate does not parse/hash/process inputs or run SOCD, and changes no mode semantics. Read once before the timer and once after End. Accumulate only if both nonzero generations match the boot-latched generation. Refusal/change sets sticky flags and invalidates corresponding evidence; no successful native sample is fabricated from a neutral/unavailable path. Measure predicate/record cost separately from raw native time; its added stack/code must be accounted. No dynamic_cast, second native evaluator or cached parallel input state.

Mode-selection measures the **one actual** selected native Activate→SetConfig→set_mode publication, including read/prepare/context/copy work. Start only for the native-selected boot request; after that real call, record successful native interval only if actual native generation is nonzero and store result is Ok/RecoveredPrevious. Failure/refusal is flagged, not folded into success statistics. Do not activate a second time for diagnostics. A subsequent generation change is INVALID under this boot-only measurement contract.

Core0 performs exactly16 adjacent time_us_32 read pairs outside polling before actual selected activation; same statistic accumulation scaffolding, recorded independently. Report raw timer calibration alongside target intervals; never subtract min/mean from raw maxima. Zero microseconds means below resolution/quantization, not free execution. Post-frame/post-activation record maxima bracket accumulation and postcondition bookkeeping using the end timestamp and an additional timer read; their own final max store lies outside that measured interval. Combined XInput observer-service max brackets the existing identity plus new diagnostic/demux/TX service after reports; it includes old observer work and is not falsely attributed entirely to new instrumentation. Scan-chunk max on each core includes bound checking, finite reads/IRQ-state save/restore and any completed-scan publication; final overhead-counter store itself remains outside its measured span. Document these limits and final compiler code.

A fixed measurement session expires at SDK uptime>=3600seconds. Snapshot assembly reads SDK time_us_64 outside the raw interval; beyond the limit, set SESSION_EXPIRED and INVALID. This makes every accepted interval shorter than one32-bit microsecond wrap, including an activation that stalled too long. No host reset/clear or timing extension command. Exact timer clock/default initialization and final flags/barriers remain source/ELF gates; timer fidelity and interrupts/ROM paths are not proven by this protocol. Device packet specifies a fresh boot and finite test coverage; no GameCube/Switch or earlier-startup timing claim.

## Stack/atomic contract retained and concretized

Entry erratum's external undefined-main and external default-core1-launch adapters only. Exact final ELF must prove interception; no SDK patch or fallback startup replacement. Core0 begins after SDK runtime_init; core1 begins after SDK trampoline/wrapper initialization. Both reserved stacks remain2048; physical4KiB banks give no extra stack authority. Each stackless own-core assembly entry validates its exact linker bounds/SP/alignment, saves/restores prior PRIMASK in registers, paints only inactive `[UsableBottom,entrySP)`, never active caller frames, and tail-calls the real entry with ABI/LR intact. No C call/push/assert/dynamic initialization in paint. Exclude bottom32 bytes conservatively for the SDK's possible guard; final actual guard layout still requires proof, never disable it. Bad bounds set fixed invalid state and preserve normal entry; do not probe guessed memory or force reset.

Each owner core scans at most16 aligned usable-stack words per loop pass; never a full-stack scan in one poll. Core0 schedules after report generation; core1 does its own finite service on its loop without cross-core pause/lockout. Read chunk uses locally saved/restored configurable-IRQ state; no other-core stack reads. No repaint after initialization. Complete scan takes at most32 chunks for the current usable range. Lowest changed address and sampled minimum SP are monotonic; report Top minus the lesser of initialized-entrySP/lowest-changed, explicitly including the conservatively occupied untouched caller region. Watermark writes can miss untouched reserved slots or coincidental paint values; neither it nor sampled SP replaces compiler/call-chain/IRQ analysis. Touching first usable word, bad SP or unknown bounds fails valid observation. Scanner/IRQ/transport stack use is included in the observation, with overhead reported, not silently removed.

Per-core local ScanState is12 u32 words listed in JSON. Each core is the sole writer/reader of its ScanState; no non-atomic access from the other core. Each publishes a20-byte mailbox: one atomic32 version plus four atomic32 payload words. All version/payload loads and stores are **sequentially consistent aligned32-bit atomics**, with compile-time and final disassembly proof they are lock-free inline loads/stores/barriers (no libatomic helper/lock/RMW retry). Owner stores odd version, four payload words, then next even version. Readers do exactly one fixed pass: version, four words, version; accept only equal nonzero even versions. On mismatch/odd/zero return PARTIAL with MAILBOX_UNSTABLE/PENDING and zero unstable fields, never spin/retry or read private ScanState. Seq-cst ordering on all words prevents an accepted mixed-version payload while avoiding C++ data races; using volatile/non-atomic payloads is forbidden. No64-bit mailbox field or torn64 access. Stop at final representable even version and set exhaustion before ABA wrap; completed scan generation likewise saturates. Native/frame/activation statistics are core0-only and copied on core0 outside its timed code, so split-sum words cannot tear cross-core.

## Storage arithmetic and path boundary

Planned mutable storage: TX160 + three20-byte stats60 + three overhead maxima12 + two48-byte ScanState96 + two20-byte mailbox40 + diagnostic RX/parser24 + transport/state16 = **408 bytes**. Source-SHA constant adds20 flash bytes; if emitted in RAM, count it for **428 bytes**, not zero. No claim that source arithmetic proves the final compiler layout. All new static including padding, state hidden in wrappers/accessor/service, generated identity constants, guards and toolchain atomic implementation must total<=512, inside existing added-static<=12288 and total<=199632. No heap; no filesystem/persistent writes; no resource limit increase. Native active+candidate<=7800, view<=560 and applicable native144/validation256 layout limits still hold; complete composed stack/IRQ depth is a separate proof against actual usable2048 reserves. Do not conflate partial frame inventory with a feasible total, or a local-layout PASS with whole-chain safety.
