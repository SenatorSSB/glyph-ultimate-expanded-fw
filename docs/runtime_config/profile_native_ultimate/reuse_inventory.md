## Findings

Working components cover all required coordinate and finite-condition semantics. The missing boundary is a native orchestration/program representation, not a second SOCD resolver or coordinate engine. Reuse remap/SOCD unchanged, adapt direction references from CustomController, extend conditions to explicit input observation domains, replace slot-bound orchestration only in a distinctly versioned native path, and preserve V1–V3 unchanged. A new general coordinate-effect type is not justified by this inventory: fixed, inline, table, selected-table and direction-source transformations already represent RF6/RF7/C-stick/null coordinates.

## Input observations and infrastructure

* `src/core/ControllerMode.cpp:8–15` copies original `InputState`, runs HandleRemap then HandleSocd once, passes the same post-SOCD input to digital then analog processing. Neither original nor pre-SOCD is retained in this type. **EXTEND_EXISTING:** a narrow per-frame immutable context with original/remapped/post-SOCD views, delivered by a default-preserving mode hook or Ultimate-specific override. No repeated preprocessing per output.
* `src/core/InputMode.cpp:57–85` **REUSE_AS_IS**: first mapping for a physical ID wins, mapped physical input is consumed, many physical sources OR into one target, unremapped inputs copy through. Restriction against duplicate physical source routing is local to remapper, not a ban on several output bindings reading one source. Nunchuk fields survive copy. The comments calling downstream data “physical” in Ultimate are imprecise: it has already been remapped and SOCD processed.
* `src/core/InputMode.cpp:17–54`, `src/core/socd.cpp:5–96` **REUSE_AS_IS**: configured ordered direction pairs, neutral, second-input priority, second-input priority without reactivation, dir1/dir2 priority, unspecified unchanged; `_socd_states[i]` preserved per configured pair. State/history must be executed once per frame. Existing source details, including simultaneous press history and pair order, remain authoritative.
* `src/modes/CustomControllerMode.cpp:74–89,152–159` **REUSE_VIA_ADAPTER**: eight profile/config-provided Button direction references plus GetDirectionButton validation and UpdateDirections. Native should read referenced post-SOCD logical IDs; reference mapping is not SOCD. Keep GameModeConfig ownership and supply associated preprocessing context in host package.
* `CustomControllerMode.cpp:54–61` **EXTEND_EXISTING**: per-output mapping permits one input to populate several output entries. Current array has one source per output, so many eligible inputs per output and bounded gates require OR contributions/conditions. Reuse principle and OutputState accessors, not combo suppression. `:39–52` combo mechanism combines several inputs to one output and excludes input ordinary functions; it is not the required independent output composition.
