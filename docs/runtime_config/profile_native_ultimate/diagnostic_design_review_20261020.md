## Why this bounded design is adequate

- **API/wire scope:** exactly one fixed16-byte D7/G/N/M GET request and fixed160-byte response on the actual XInput single-reader path. It exposes selected counters/flags/source SHA, not addresses or memory, and offers no mutation/reset/configuration/selector/depth/length-controlled work. Independent arithmetic verifies all response offsets cover0..159 exactly once, request fields total16, and declared mutable components total408. Explicit serialization and unknown-bit/version/length rejection avoid struct-layout or future-version guesses.
- **Old identity/viewer behavior:** existing identity16/72 constants, status and codec/Consume/Expire/layout remain exact, except the const HasPartialFrame accessor. Identity owns its partial opaque body. Diagnostic matching is only tentative before all4 magic bytes; a mismatch reconsiders the current byte, preserving a5 after stray d7/prefix. Complete diagnostic ownership prevents embedded identity magic from being executed. The32-read/one-response limit and same-Poll identity priority, no queue, drop rules,192-byte diagnostic admission and1-second admitted-response limit bound RX/TX work. Existing25-byte viewer record, reserve and source cadence remain unchanged. Final tests must prove these statements against actual code; prefix uniqueness by itself is not the argument.
- **Measurement truth:** native generation comes from the actual owned/published/valid latched engine, queried outside the raw interval; failed/native-unavailable/changed-generation paths cannot manufacture successful samples. The one real UpdateOutputs interval includes remap and stateful SOCD exactly once; activation brackets the one real boot Activate→SetConfig→publication, without replay. SDK microsecond timestamps include IRQ/stall/quantization, fixed adjacent-read calibration is reported separately, and record/service/scan overhead is explicitly bounded and labeled. Saturation and one-hour session expiration avoid silently accepting counter/timer wrap or claiming cycle/WCET/uninstrumented values.
- **Entry feasibility:** the corrected hooks use crt0's external undefined main and Arduino main's external default multicore_launch_core1 call, not the withdrawn same-object runtime_init/main1 wraps. Source/previous exact ELF make interception plausible; only final linked proof can establish it. Core1 remains on the original default launcher/reserved stack, validates the expected actual main1 target and single supported launch, and preserves ordinary behavior with invalid observation for unexpected alternatives. No SDK cache/startup replacement or extra stack is needed in the proposed path.
- **Painting/ownership:** each stackless own-core entry masks configurable IRQs while preserving prior PRIMASK and ABI/LR, validates exact bounds/SP/alignment, paints only inactive usable words below entrySP, leaves caller frames intact, and tail-calls the real entry. Excluding the aligned bottom32 bytes agrees with the pinned SDK guard's rounded32-byte MPU subregion; final symbols/guard compile setting remain mandatory proof. Paint begins after SDK runtime/core launch initialization, so earlier peaks stay unknown. No repaint, cross-core stack read, arbitrary address or cross-core pause is allowed. Sixteen-word chunks and conservative caller-area accounting bound service and keep write-watermark/sample-SP limitations honest.
- **C++ concurrency:** each48-byte private ScanState is owned by one core. Mailboxes use aligned32-bit atomic version **and payload** words, all seq-cst. With no version wrap/ABA, equal nonzero even first/last versions around one fixed six-load pass exclude mixed publications in the seq-cst total order. No non-atomic payload race,64-bit tear, retry/spin or reading the other core's private state is needed. The explicit inline lock-free load/store/barrier proof is essential on ARMv6-M; design approval does not assume every std::atomic operation is lock-free. Concretely, compile-time assertions cover word size/alignment and layout; method-specific object/final-ELF inspection must prove only the used seq-cst loads/stores are inline bounded LDR/STR/barrier sequences with no helper/lock/RMW. Do not require std::atomic<uint32_t>::is_always_lock_free to be true: its false result can include unsupported RMW operations that this design forbids and does not invalidate directly proved load/store methods.
- **Limits/scope:** the408-byte plan (428 if SHA constant lands in RAM) fits the512 subcap arithmetically and includes named parser/TX/stats/scanner/mailboxes/state. It grants no extra total budget: padding/hidden statics/atomic helpers/wrapper state, native7800/view560/frame144/validation256, added static12288/total199632, flash/partition/filesystem/reserve and both2048 stacks all still apply. Actual usable stack can be smaller because of guard exclusion.
