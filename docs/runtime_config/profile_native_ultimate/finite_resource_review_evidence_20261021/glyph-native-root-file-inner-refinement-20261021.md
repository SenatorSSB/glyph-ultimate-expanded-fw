## State invariant being used

The owner domain admits broad **structurally valid recoverable LittleFS histories**, with unrelated/foreign directories, positive-orphan and PENDING_MOVE recovery. It does not require a pristine, flat, Glyph-only, freshly formatted or clean initial filesystem. CRC-valid bytes that alias a root pair from a foreign DIRSTRUCT or create cyclic namespace ownership are not a structurally valid LittleFS namespace/history. They fall under the existing no-arbitrary-corruption boundary. This report does not assert that Glyph Begin exhaustively validates that invariant; it uses the inherited supported-state domain, rather than a newly introduced runtime gate or refusal.

The essential invariant is stronger than merely saying the file's current root pair has no DIRSTRUCT parent: **every metadata predecessor reached by root relocation propagation is also in the parentless root-prefix chain**. The global tail list begins at reserved pair{0,1}. Root head/split-tail segments, including an earlier reserved prefix after superblock expansion moves the internal root pointer, form a contiguous initial region. DIRSTRUCT entries reference nonroot directory heads, never the root head, a root split tail, or that reserved prefix.

This is maintained by the actual source operations. Format starts at the reserved root pair. dir_split allocates and compacts a tail, then inserts it directly after its source, preserving the previous split/tail state; a split at0 may update the internal root to the new tail without giving it a DIRSTRUCT parent. mkdir finds the end of its parent's split chain and links the new foreign directory head there, after all that parent's same-directory segments; a nested mkdir outside root cannot insert inside the root prefix. Rename moves entry/attributes and directory-head references; it does not move root into a DIRSTRUCT entry (root id0x3ff is rejected). Remove/drop steals the removed segment's tail/split ownership, without inserting an unrelated directory head into the middle of a root split chain. Relocation replaces a half pair and updates the same logical predecessor/reference; it changes addresses, not directory ownership. Successful recovery restores intermediate parent/predecessor references. A valid allocator cannot manufacture an alias of a live root metadata block as a foreign directory head.

Thus fs_parent's full global scan may read many foreign directories, but cannot find a DIRSTRUCT matching a root-prefix pair in such a namespace. When fs_pred supplies the predecessor of a root split segment or expanded root head, it supplies another root-prefix segment, not an arbitrary foreign directory parent. This predecessor closure is what prevents a later loop iteration from escaping the parentless route.

## First Remove and recovery barrier

Capture proceeds only after CheckedRemove(/ultimate-migration.tmp) acknowledges Ok, including its normal NotFound translation. rawremove calls forceconsistency BEFORE path lookup; demove then deorphan(true) each propagate failure. In the valid source-history domain, a plain valid metadata fetch does not return lookup-NOENT: force's parent NOENT is explicitly handled, and a referenced DIRSTRUCT data tag is present absent corruption/concurrent mutation. Thus the translated path-NOENT result still follows the completed consistency phase; the translation is not used to bless a malformed missing-parent-data error.

The true deorphan scan checks the entire linked metadata list. It removes full orphans, resolves half-orphan pair mismatches, and restarts the same activation if its repairs generate more relocation work. Demove clears the outstanding move before its returned commit/repair and the subsequent true scan. On successful return the actual recovery records are resolved. A phantom residual positive counter is not assumed zero: a later scan may remain enabled, but a counter with no actual orphan does not select a mutation branch. This conclusion relies on valid recoverable history's gstate/namespace consistency, not on a successful return mechanically zeroing the counter (it does not).

The first Remove is charged its **generic** U1384/M1496 in its small phase. It is not given the root-output bound. If the same named path is an empty directory, rawremove must perform its directory-specific decrement/drop and any returned repair before it returns success. A nonempty or split directory refuses and stops capture. Directory relocation repair is a half-pair desync: compact preserves the active old half while replacing the other half, pair_cmp recognizes the overlap, and deorphan(false) handles the mismatch without its powerloss-only full-orphan branch. A full intentionally removed directory is unlinked by the final acknowledged drop. Failure at any of these stages stops before copy. This addresses the foreign-directory-at-temp-path case without silently assuming the name was absent/a regular file.

After that barrier the input is constructed/opened read-only and cannot set WRITING, create a DIRSTRUCT, rename a directory or generate pending MOVE. The output is the original single-component root regular filename. Its only subsequent filesystem operations are root file Open/Write/Sync/Close. No other core0, IRQ or core1 writer reenters the filesystem during this synchronous sequence. A previous failed capture is not carried through this refinement unchecked: a later capture again begins with the generic true-consistency Remove barrier.

## Why returned deorphan is absent

orphaningcommit initializes local orphans=false. The **only** assignment true occurs when fs_parent finds a DIRSTRUCT parent and updating that parent itself returns RELOCATED. Its predecessor-only relocation loop and dropped-empty-split path do not independently set that flag. The root-prefix invariant excludes hasparent on the initial root file.m pair and on every propagated predecessor. Consequently this root operation cannot return ORPHANED, and the commit wrapper cannot invoke its returned deorphan(false) child.

This does not exclude compaction, splitting, wear relocation, allocator traversal, bad-block retry, CTZ allocation, CRC readback or masked flash. All remain fully counted in the ordinary1024/1136 U/M subtree. It excludes exactly the additional retained deorphan176 layer for these root-file commits. The second writable Open's initial forceconsistency is also not simply removed: with no move and no actual repair remaining it can execute a read-only deorphan scan with U516 (force64 + deorphan176 + parent fetch/matcher/read276). Adding raw/public/Checked184 gives700, below the root creation commit1208. A residual counter alone is therefore safely included.
