# GP-CONFIG-021 persisted recovery host proof

This candidate host proof is based on `c6887115f2e44f0803eb0956ebb574633cec53be`. The CLI requires a committed candidate with that sole parent and exactly the six adopted critical source changes. GP-VAL-038 owns later authenticated historical replay and admission; this checker does not relax its candidate contract.

The checker compiles literal production translation units against the frozen generated GP-PROV-014/Nanopb 0.4.9.2 closure. Every C and C++ unit uses the same enum layout in each run: `-fshort-enums` or `-fno-short-enums`. Address, undefined behavior, enum and shift sanitizers are fatal. Each compiler dependency emitted by `-MMD` must belong to the independently pinned finite input catalogue. Clang's selected SDKSettings metadata is explicitly recorded with its resolved path, SHA-256 and compiler command. Other external application inputs are rejected. Two unchanged TUs have exact macOS-only warning suppressions: console_detection for its existing uint8 versus -1 comparison (`-Wno-tautological-constant-out-of-range-compare`), and NintendoSwitchBackend for its old field designators (`-Wno-gnu-designator`). The execution record binds both original diagnostics, source hashes and flags. No other diagnostic is filtered. Compiler/link stderr and runtime stderr must otherwise be empty. The first strict warning rejection log is retained.

## Actual suites

- Semantic: 1,077 short / 1,173 ordinary cases. All 20 generated top and nested extent classes are checked at zero, bound and bound+1, including last nested rows. Reference cases retain zero and valid remaps, cover full uint32 values through UINT32_MAX, wrong mode types, existing error order and formatted versus static NUL packet lengths. The C020 binding validator stays literal and unchanged.
- Persistence: 326 cases per layout. Real CRC/header checks and the actual Nanopb decoder exercise malformed, truncated, partial and repeated inputs, valid-CRC integer overflows, unknown fields, decoder I/O failures, mount/configuration refusal, unavailable storage methods and stable callback installation. Failed loads preserve every caller object byte and stored bytes; valid loads follow each failure. Unknown-field skipping uses the real Nanopb scratch path; it does not establish execution of the reader's redundant null-buffer branch.
- SET: 868 cases plus one fresh-process missing-callback case per layout. The actual handler, decoder, validation callback and SaveConfig execute. Every actual write observes the complete prior live Config; publication follows successful save. Rejections preserve full live bytes and stored bytes. Failed write-open preserves the prior file before truncation. Post-open failed writes and disk atomicity are outside this proof.
- Whole startup: 40 cases per layout run the actual application and consumer graph: valid, Configurator, rejected, missing/open, bad defaults, mount/configuration failure and pre-load MB1; early, concurrent and late core1 schedules; display success/failure. Refusal clears both scratch words, prevents normal constructors and stays permanent across poisoned-pointer loop calls. Core1 redraw and failed-display ownership are checked. Actual named constructor entry observations require exact dladdr symbol addresses; the two NeoPixel template entries use nm addresses relative to the actual executable image base. Counts are entry events, not object counts. The runner owns the constructor-offset environment.

## Negative and identity controls

Sixteen mutants per layout are compiled and linked using the unchanged positive object graph: fullwidth narrowing, autoformat, ignored mount failure, missing/bypassed callback, early caller publication, saving rejected stored Config, SET validation bypass, each scratch omission, failed-display draw, omitted initial recovery draw, omitted core0 gate, omitted core1 redraw, missing return after load refusal and missing setup1 refusal branch. Each must fail during execution. Compile or link failure does not count as runtime evidence.

Ten additional architectural source checks cover exact extraction/order, private candidate reset, SDK initialization and boot gates. Some are redundant with other implementation behavior; their rejection is reported as a source contract check. Closed disposable identity copies test omission, substitution, executable mode, symlink and parent symlink, plus independently pinned fixture substitution. HEAD, index stage0, live bytes, regular100644 modes and index flags must match at entry and exit; staged expected bytes cannot hide a different committed input. The literal backend_init adapter changes only the default argument parameter declaration name. SaveConfig's successful body equals the accepted original, apart from its availability guard.

## Limits and retained observations

Platform filesystem, display, GPIO, physical buses and COBS transport are host seams. SDK synchronization is represented by a host mutex; this does not prove the RP2040 runtime. Configurator mode uses its existing supported mode1 in the positive test; earlier mode0 observer failures are preserved. Initial MMD fail-closed attempts and startup instrumentation failures remain in the preparatory evidence under `/private/tmp/glyph-config021/host-work`; they were harness defects, not accepted source results.

This proves no firmware build, target ABI, actual COBS wire framing, physical acceptance, power-loss recovery or safety of every admitted Config. Nunchuk and root cause remain unclaimed. All original historical checker, fixture, harness, schema and decoder bytes remain separate immutable observations; this new proof does not reseal them.
